# Mac Development Workflow

This repository maintains `kenkenchu/dusk-player-mac` as a native Mac-first
app alongside the maintained tvOS client for Apple TV HD. Preserve unrelated work and follow `AGENTS.md` before editing or publishing.

## Source of Truth

- `project.yml`: `Dusk-macOS`, `Dusk-tvOS`, and `DuskTests`, deployment
  version, arm64 architecture, resources, signing, and framework linkage.
- `Dusk.xcodeproj`: generated by XcodeGen; never edit it by hand.
- `STYLE.md`: Mac UI rules and tokens.
- `docs/codebase-map.md`: source ownership and extension points.
- `Frameworks/`: downloaded desktop VLC and locally built DuskDovi; git-ignored.
- `Native/DuskDovi/`: pinned Rust crate, C interface, and dependency notices.

Mobile targets, simulator/run helpers, Top Shelf extension, mobile VLC build
patches, alternate icon generators, and TestFlight publishing scripts are gone.
The archived upstream instructions do not apply to this fork. The new
`Dusk-tvOS` app has a separate [device workflow](tvos-prototype.md) and
`scripts/build_tvos.sh`; it does not use desktop playback frameworks.

## Bootstrap and Build

Install Xcode 26+, XcodeGen, rustup, and the Metal toolchain. Open Xcode once to
finish setup and make sure `xcodebuild -version` selects the full installation.

```bash
brew install xcodegen
xcodebuild -downloadComponent MetalToolchain
./scripts/build_macos.sh
```

The script installs desktop dependencies, regenerates the project, builds
`Dusk-macOS`, and verifies the app's nested signatures. The build also checks the
embedded VLC binary against the fetched framework. It never launches the app
or runs tests. Output: `.build/macos/DerivedData/Build/Products/Debug/Dusk.app`.

The supported app is arm64 on macOS 26+. Only the desktop VLC framework and
`macos-arm64` DuskDovi slice are needed. `DuskTests` is a native hosted test target
for retained model/service tests; tests are not part of the routine agent gate.

## VLCKit Bootstrap

`ci_scripts/install_macos_vlckit.sh` downloads stock VideoLAN desktop VLCKit
3.7.3 from its official archive and verifies its pinned SHA-256 before staging
`Frameworks/VLCKit.xcframework`. Never weaken that checksum or substitute an
unverified framework. The source/version and stamp live in the installer.

It has no Dusk TrueHD capability stamp, so the resolver and player track logic
require another locally playable audio track; Plex audio conversion is prohibited. This fork does not depend on
private upstream mobile VLC releases. VLC stays dynamically linked; preserve
its LGPL license and avoid stale embeds.

## DuskDovi Bootstrap

`ci_scripts/install_dusk_dovi.sh` builds an arm64 macOS static library from
`Native/DuskDovi`. It stamps a hash of the crate, lockfile, toolchain, build script,
and macOS deployment target, then reuses the result until those inputs change.
`scripts/build_dusk_dovi_xcframework.sh` forces a rebuild.

Use rustup's pinned cargo and rustc binaries. Homebrew's binaries may appear
first on PATH; the script resolves both with `rustup which`. Do not rely on a
bare `cargo` command. Changing the C header requires the matching ABI version
and bridge validation updates. New crates need notices in the app and
`Native/DuskDovi/THIRD_PARTY_LICENSES.md`.

## Metal Toolchain

Run `xcodebuild -downloadComponent MetalToolchain` after an Xcode upgrade if the
compiler is missing. Check `xcrun --sdk macosx metal --version`. The CI bootstrap
can import an exported bundle from Xcode's download cache before downloading.
A missing shader diagnostics file may just mean the Metal compiler never ran.

## Signing and Local Network Permission

The normal build script signs the entire app with its network sandbox
entitlements. Set `DUSK_MACOS_SIGNING_IDENTITY` to an installed Apple-issued
identity when available; otherwise it uses ad hoc signing. Distribution signing
and notarization are separate from a local development build.

For repeated local builds, use the same Apple Development identity. Ad hoc
signatures identify a particular build, so changed builds can repeatedly prompt
for permission to read existing Plex credentials from the login Keychain.

```bash
security find-identity -v -p codesigning
export DUSK_MACOS_SIGNING_IDENTITY='Apple Development: Your Name (IDENTIFIER)'
./scripts/build_macos.sh
```

Copy the exact identity name from the command output. Export it in each build
shell (or configure it in your local shell environment); the build script does
not remember a previous invocation's identity. Agents must explicitly select the
installed identity rather than silently reverting to ad hoc signing. Switching
from ad hoc to certificate signing may require one more Keychain approval.

To create an identity, open Xcode → Settings → Apple Accounts, sign in, select
your Personal Team, then Manage Certificates → + → Apple Development. Local
development can use a free Apple Account. Keep the private key in the login
Keychain; never commit or share it.

If `security find-identity -v -p codesigning` reports no valid identities:

- Run `security find-identity -p codesigning` without `-v` to distinguish an
  absent identity from an installed identity that fails validation.
- In Keychain Access → login → My Certificates, confirm the development
  certificate has its matching private key and is within its validity dates.
- Check the issuer's intermediate certificate. Apple Development certificates
  issued by WWDR G3 need the matching **Worldwide Developer Relations – G3**
  intermediate from [Apple PKI](https://www.apple.com/certificateauthority/).
  An older WWDR intermediate does not replace G3. Install the public intermediate
  in the login Keychain and rerun the identity check. Use system-default trust;
  do not work around validation failures with “Always Trust”.

On this workstation, installing the missing WWDR G3 intermediate made the
existing Apple Development identity valid. A subsequent certificate-signed build
passed the build script's signature verification and the user confirmed it works.


Keep `ENABLE_DEBUG_DYLIB=NO` so the main executable contains app-specific code and
has its own UUID. Local-network privacy uses signature/executable identity;
Apple-issued identities are preferred for stable permission tracking. See
[Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy).

If sign-in succeeds but local servers time out, check System Settings → Privacy
& Security → Local Network and allow Dusk, then Retry. The Info.plist usage
string and sandbox entitlements do not grant this permission. “Local network
prohibited” in the OS log indicates a privacy block. Do not change system-wide
privacy defaults or run the app as root to bypass it.

## Project Generation and Verification

Run `xcodegen generate` after project changes or source additions/removals/renames.
Commit the generated project and scheme changes with the source changes.

After code changes, run `./scripts/build_macos.sh`. For a compiler-only check
once dependencies exist:

```bash
xcodebuild -project Dusk.xcodeproj -scheme Dusk-macOS -configuration Debug \
  -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath .build/macos/DerivedData CODE_SIGNING_ALLOWED=NO build
```

The unsigned product is only a compiler check. Rebuild with the signing script
before handing an app to the user. Do not launch the app or run tests unless
explicitly requested. Docs-only edits need link/reference and diff checks.

## Maintaining the Fork

`origin` is `git@github.com:kenkenchu/dusk-player-mac.git`; `upstream` is
`git@github.com:marvinvr/dusk-player.git`. New fork work is committed and pushed
to `origin` on the current branch, normally `main`.

Start with a clean tree, then review and merge upstream changes deliberately:

```bash
git fetch upstream
git merge upstream/main
./scripts/build_macos.sh
git push origin main
```

Resolve shared Swift/project conflicts while preserving the Mac-only scope;
do not restore removed mobile targets or deployment workflows. Do not force-push
shared `main` or push fork-specific work to `upstream`. Inspect the complete diff
before publishing, keep unrelated work out, and never commit frameworks, local
builds, auth tokens, signing credentials, or machine-specific files.

## Two-Platform Build Gate

Both build scripts regenerate XcodeGen inputs and run
`scripts/verify_platform_boundaries.py` before compiling. TV/shared/project
changes require both signed builds. The Mac signing identity and sandbox/
executable identity settings remain unchanged. TV uses its own development
profile and team setting; see [TV device workflow](tvos-prototype.md).
A successful compile is not visual or input parity. Do not launch apps or run
tests without explicit authorization; the user verifies device behavior.
